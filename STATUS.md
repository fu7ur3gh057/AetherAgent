# Aether: статус и план (на 20.11.2026)

Личный ИИ-агент в Telegram. Подробности по устройству и настройкам: `README.md`. Здесь: что сделано, что осталось проверить,
что решено и с чего продолжать.

## Что сделано

Архитектура: hexagonal ядро (`src/core`) + адаптеры (`src/adapters`) + возможности (`src/capabilities`) + сборка (`src/app`).
Правило зависимостей проверяется тестом `tests/test_architecture.py`.

| Область | Что есть |
|---|---|
| Базовое | Telegram (aiogram), белый список, Postgres, история, `/history`, `/search`, `/reset`, меню команд |
| Модели | Gemini (основной) и Claude через порт `LLMProvider`; учёт токенов, дневной лимит, `/usage` |
| Почта | Gmail: поиск, чтение, отправка и ответы **только с подтверждением кнопкой**; недоверенные данные в явном блоке |
| Память | Заметки о владельце в промпте, `/memory`, `/forget`; защита: после чтения писем/страниц/вложений запись требует подтверждения |
| Напоминания | Разовые и повторяющиеся (daily/weekdays/weekly), кнопки +10 мин/+1 час, опоздавшие доставляются |
| Голос | Whisper (локально, `faster-whisper small`) основной, Gemini запасной (`STT_FALLBACK`); очереди пока нет |
| Файлы | Фото, PDF, DOCX, текст, альбомы; вложение недоверенно |
| Интернет | `web_search` (Gemini + Google, отдельным запросом: поиск нельзя совмещать с функциями), `read_url` (защита от SSRF) |
| Наблюдатели | Проверки по расписанию, уведомление только о новом; `/watchers`, `/unwatch` |
| Сводка | Разделы `mail,weather,rates,news,sports`, `/digest`, город/клубы из настроек или памяти |
| Надёжность | Бэкапы БД (systemd-таймер, скачивание на Mac, восстановление), оповещения (токен Google, сбои, лимиты), CI |
| Страховки модели | «Ленивые» ответы («нет доступа», «сейчас поищу») повторяются один раз с напоминанием про инструмент |

Тесты: 177 (все зелёные в чистом окружении), CI на GitHub: тесты, бэкапы на настоящем Postgres, образ, синтаксис Ansible.

## Состояние на сервере (проверить в первую очередь)

Последняя версия **выкачена ли на сервер, не подтверждено**. Порядок:

```bash
cd ansible
./deploy.sh deploy     # код + миграции до 0005, зависимость httpx
./deploy.sh gmail      # токен Google с датой выдачи (для предупреждения о сроке)
./deploy.sh env        # только если менял .env (TIMEZONE, DIGEST_*, WATCHER_*, WEB_SEARCH_*)
```

Затем в Telegram проверить живьём то, что до сих пор проверялось только тестами и прямыми вызовами моделей:
- `/digest` и утренняя сводка по таймеру (`DIGEST_TIME`);
- `read_url` на настоящей ссылке; создание наблюдателя фразой и первое уведомление, `/watchers`;
- фото и PDF в чате; оповещения (сообщение «🟢 Aether запущен» приходит при старте).

## Открытые пункты

- **Токен Google в режиме Testing протухает через 7 дней** (выдан 19.11 вечером, около 26.11). Бот предупредит примерно за 2 дня.
  Обновить: `.venv/bin/python scripts/google_auth.py`, затем `./deploy.sh gmail`. Постоянное решение: публикация приложения Google
  (страницы на подтверждённом домене + публичный колбэк), нужна правка общего nginx на сервере: **согласовать, не делать молча**.
- Ночная копия БД по таймеру (03:15-03:25 по времени сервера) ещё ни разу не отработала сама; восстановление через playbook не
  репетировалось на боевой базе (проверены его части).
- Claude как провайдер не запускался с настоящим ключом (код и структура запроса есть).
- Тарифы поиска Google и лимиты Gemini не проверены; стоит дневной лимит поисков (`WEB_SEARCH_DAILY_LIMIT`, 50).
- Запасной Gemini для голоса отправляет аудио в Google; для режима «только локально» поставить `STT_FALLBACK=off`.

## Грабли, на которые уже наступили

- Gemini: системная инструкция и вызов функций работают только в `v1beta`; поиск нельзя совмещать с функциями в одном запросе.
- `faster-whisper` ломается с `av>=14` (закреплено `av<14`).
- Образ Postgres на первом старте поднимает временный сервер: ждать готовность по TCP (`-h 127.0.0.1`), не по сокету.
- Тесты зависят от глобального реестра инструментов: каждый файл в `tests/` запускается отдельным процессом.
- Модель иногда не вызывает инструмент, а обещает или отказывается; для этого страховка в `src/core/agent.py` (`LAZY_RE`).
- На Mac владельца временами отваливается системный DNS (SERVFAIL, в Docker-сборке тоже); публичные DNS при этом отвечают. Повтор помогает.
- Общий VPS: на нём работают другие проекты (прод). Aether живёт независимо в `/opt/aether`, контейнер бота ограничен 2 ядрами и 3 ГБ.
  Общий nginx другого проекта не трогаем без согласования.

## Следующий большой шаг: многопользовательский режим (план согласован в общих чертах)

Цель: до 20-30 человек по приглашению владельца; каждый вводит свой ключ Gemini или Claude и подключает свою почту.

Решения владельца:
- масштаб 20-30 человек; готов хранить чужие данные (с шифрованием и удалением по запросу);
- каждый платит за модель своим ключом (BYOK);
- пользователи Claude распознают голос локальным Whisper через **очередь**; в перспективе полный переход на Whisper;
- почта: сначала IMAP + пароль приложения, Google OAuth позже (при ≤100 пользователей платной верификации не требует, по сведениям
  Google; условия проверить в их документации; нужен публичный колбэк и публикация приложения).

Этапы:
0. Решения: стенд на втором Telegram-боте; мастер-ключ шифрования в `.env` + копия вне сервера; языки (ru + en?); поиск для
   пользователей Claude (встроенный поиск Anthropic или пока без поиска).
1. Ядро: 1а `users`/`invites`/`user_secrets` (шифрование), проверка доступа вместо `ALLOWED_USER_IDS`, владелец становится админом №1
   (поведение не меняется); 1б всё «по пользователю» (модель и ключ, пояс, язык, лимиты, расход, сводка, напоминания, наблюдатели,
   доступность инструментов) + **тесты изоляции**; 1в вход и админка (`/invite`, `/start <код>`, ввод ключа с удалением сообщения,
   `/settings`, `/key`, `/delete_me`, `/users`, `/revoke`).
2. Whisper как единственное распознавание: очередь по кругу между людьми, 1-2 воркера, лимит минут на человека, замер под нагрузкой.
3. Почта как плагин: порт `MailProvider`, адаптеры Gmail API и IMAP/SMTP (чтение закреплено в коде, отправка с подтверждением), `/mail`.
4. (по желанию) Google OAuth с веб-страницей и публикацией приложения.
5. Эксплуатация: лимиты частоты, шифрование бэкапов, политика конфиденциальности, инструкция для друзей, внешний монитор.

Ожидается от владельца перед этапом 1а: стенд на втором боте (да/нет), языки (ru/en), согласие начать с IMAP.
