# Aether

Личный ИИ-агент в Telegram. Ядро не зависит от провайдера LLM, канала связи и хранилища.

## Локально

```bash
cp .env.example .env   # заполнить токены и POSTGRES_PASSWORD
docker compose up -d --build
docker logs -f aether_bot
```

## Деплой (Ansible, /opt/aether на VPS)

```bash
cd ansible
./deploy.sh setup    # первый раз: clone + .env + запуск
./deploy.sh          # обновление: pull + rebuild
./deploy.sh env      # перезалить .env
./deploy.sh logs
```

## Архитектура: hexagonal ядро + модули возможностей

```
src/
├── core/            # ядро, ничего не знает о внешнем мире
│   ├── agent.py     # цикл агента
│   ├── messages.py  # нейтральный формат сообщений
│   ├── ports.py     # интерфейсы: LLMProvider, MessageStore
│   └── tools.py     # реестр инструментов и @tool
├── adapters/        # реализации портов
│   ├── channels/telegram/
│   ├── llm/         # claude.py, gemini.py
│   └── storage/postgres/
├── capabilities/    # что агент умеет: папка на возможность (clock, gmail, ...)
├── app/             # composition root: config, wiring, main
└── prompts/system.md
migrations/          # Alembic
ansible/             # деплой
tests/
```

Правило зависимостей (проверяется `python tests/test_architecture.py`):
- `core` не импортирует ничего, кроме `core`;
- `adapters` и `capabilities` зависят только от `core` и не знают друг о друге;
- `app` собирает всё вместе.

Новая возможность: папка в `src/capabilities/<name>/` с `tools.py` (`@tool`) и строка в `capabilities.load_all()`.
Новый провайдер LLM: файл в `src/adapters/llm/` и ветка в `app/wiring.py`.

## Gmail (чтение и отправка)

1. Google Cloud: проект, Gmail API, OAuth-клиент **Desktop app**, JSON сохранить в `data/google_client.json`.
   В Data access добавить scopes `gmail.readonly` и `gmail.send`.
2. `.venv/bin/python scripts/google_auth.py` — браузер, согласие, получится `data/google_token.json`.
3. `cd ansible && ./deploy.sh gmail` — токен на сервер (600) и перезапуск бота.

Без `data/google_token.json` возможность выключена, бот работает как раньше.
Если токену выдан только `gmail.readonly`, доступны лишь поиск и чтение; инструменты `gmail_send` и `gmail_reply`
регистрируются, только когда токен содержит `gmail.send`.
Отправка всегда идёт через окно подтверждения: адресат (для ответа берётся из исходного письма), тема и полный
текст (до 3000 символов, до 5 адресатов); ответ уходит только отправителю, без reply-all.
Всё из почты отдаётся модели в блоке `<untrusted_email_data>` как недоверенные данные.

## Подтверждение действий

Инструмент с `risk="write"` (`@tool(..., risk="write", describe=...)`) не выполняется сразу:
владелец видит в Telegram описание действия, собранное из реальных аргументов, и кнопки
«Подтвердить / Отклонить». Отказ, таймаут (120 с), ошибка или отсутствие канала подтверждения = действие не выполняется.
Тесты: `PYTHONPATH=. python tests/test_confirmation.py`.

## Часовой пояс и утренняя сводка

В `.env`: `TIMEZONE=Asia/Baku` (IANA-имя) влияет на «сегодня/вчера» в ответах, `/history` и расписание.
`DIGEST_TIME=08:30` включает утреннюю сводку почты (по `DIGEST_DAYS`, 1=пн ... 7=вс); пусто = выключено.
Планировщик встроенный (`src/app/scheduler.py`): запуск раз в день фиксируется в таблице `job_runs`, после рестарта
не повторяется, пропущенный запуск догоняется в течение 3 часов, при сбое 3 попытки с паузой 5 минут.
После изменения `.env` на Mac: `cd ansible && ./deploy.sh env`.

## Долгая память

Короткие заметки о владельце (до 100 штук по 300 символов) лежат в Postgres и подставляются в промпт каждого запроса.
Бот сохраняет их сам (`memory_save`), когда ты просишь «запомни …» или сообщаешь устойчивый факт; `/memory` показывает,
`/forget N` удаляет. Эмбеддинги и `pgvector` пока не нужны: заметок немного, и они помещаются в промпт целиком.

Защита от prompt injection: если в этом ходу бот уже читал письма (инструмент помечен `untrusted_output`), то
`memory_save` и `memory_forget` (`confirm_when_tainted`) требуют подтверждения кнопкой, чтобы письмо не могло тихо
изменить память.

## Напоминания

Просьба «напомни завтра в 10 позвонить Руслану» превращается в запись в Postgres (инструмент `reminder_create`;
время считается по `TIMEZONE`). Фоновый сервис (`src/app/reminders.py`) каждые 15 секунд рассылает сработавшие:
сообщение с кнопками «+10 мин», «+1 час», «Ок». Повторы: `daily`, `weekdays`, `weekly` (время сохраняется по часам
владельца, в том числе при смене лета и зимы). Если бот был выключен, напоминание придёт после запуска с пометкой «опоздало»;
при сбое доставки 5 попыток. Команды: `/reminders`, `/cancel N`. После чтения писем создание и отмена требуют подтверждения.

## Голосовые сообщения

Голосовое (а также аудиофайл и «кружок») бот скачивает, расшифровывает и отвечает
на него как на обычное сообщение (расшифровку обратно не присылает). Лимиты: `VOICE_MAX_SECONDS` (300 с) и 10 МБ. Пересланное голосовое передаётся модели
как недоверенные данные, а не как команда владельца.

Распознавание выбирается `STT_PROVIDER` (по умолчанию авто):
- `whisper` (основной): локальный `faster-whisper` на CPU, аудио остаётся на сервере. Образ собирается с ним по умолчанию
  (`WITH_WHISPER=1`), модель `STT_MODEL=small`, `WHISPER_CPU_THREADS=2`; контейнер бота ограничен 2 ядрами и 3 ГБ.
  Модель грузится при старте в фоне и кэшируется в `data/whisper`.
- `STT_FALLBACK=gemini`: если Whisper упал с ошибкой, аудио отправляется в Gemini (запасной вариант; `off` = только локально).
  Тишина ошибкой не считается и в облако не уходит.
- `gemini`: распознавание только через Gemini (~2 с на файл, точнее Whisper `small`). Инструкция передаётся как
  `system_instruction` (в `v1beta`), иначе на тишине модель повторяла текст промпта.
- `off`: голосовые выключены.

Замер на VPS (6 ядер, 2 потока, beam 1, синтетическая русская речь): `small` RTF ≈ 0,4 (голосовое на 30 с ≈ 10 с),
память ≈ 1 ГБ, первая загрузка модели ≈ 20 с (греется при старте); `base` быстрее (RTF ≈ 0,16), но заметно хуже по-русски.
Повторить замер: `scripts/stt_bench.py`. Ограничение: faster-whisper не работает с `av>=14`, поэтому в Dockerfile `av<14`.

## Резервные копии БД

Ежедневный дамп Postgres (`pg_dump -Fc`) делает systemd-таймер на сервере (03:15 по времени сервера, `Persistent`: пропущенный
запуск догоняется) в `/opt/aether/data/backups`, вне docker-томов; остаются 14 последних. Каждый дамп проверяется
`pg_restore --list` до удаления старых. Копия на том же сервере не защищает от его потери, поэтому есть скачивание на Mac.

```bash
cd ansible
./deploy.sh backup-setup              # один раз: скрипт + таймер + первая копия
./deploy.sh backup [метка]            # копия сейчас (метка, например pre-migration: не ротируется)
./deploy.sh backup-pull               # скачать последнюю на мак в ~/aether-backups (права 700)
./deploy.sh backup-status             # копии, таймер, последние запуски
./deploy.sh backup-restore <файл>     # имя файла на сервере или путь к файлу на маке
```

Восстановление заменяет данные: перед ним автоматически делается копия `pre-restore`, бот останавливается, после
`pg_restore` запускается снова (миграции применяются при старте). Если восстановление упало, бот остаётся остановленным.
Контроль: бот раз в день (`BACKUP_CHECK_TIME`, 09:00) проверяет, что копия не старше `BACKUP_MAX_AGE_HOURS` (36), и пишет
в Telegram, если это не так; молчание означает порядок. Проверка на настоящем Postgres: `bash tests/integration_backup.sh`.

## Оповещения о проблемах

Общий механизм `src/core/alerts.py`: любой слой вызывает `raise_alert(ключ, текст)`, доставка идёт владельцу в Telegram,
повтор с тем же ключом подавляется на время cooldown (нет спама). Бот сам пишет, когда:
- токен Google не работает (сразу при первой ошибке, и ежедневно в `HEALTH_CHECK_TIME` с проверкой обновления);
- токену Google осталось ~2 дня жизни (режим Testing, `GOOGLE_TOKEN_MAX_AGE_DAYS=7`; нужна дата выдачи, её пишет `google_auth.py`);
- Whisper упал и голосовое ушло на запасной Gemini (аудио ушло в Google);
- напоминание не доставлено после 5 попыток; утренняя сводка не собралась;
- резервная копия БД устарела (см. выше);
- дневной лимит токенов на 80% и на 100%;
- бот запущен (`STARTUP_NOTICE`): видно рестарты и деплои.
Недоступность самого бота так не обнаружить (оповещать некому): для этого нужен внешний монитор.

## Расход токенов и лимит

Каждый запрос к модели учитывается (вход и выход, по модели и дню в твоём часовом поясе) в таблице `llm_usage`.
`/usage` показывает расход за сегодня и неделю. `DAILY_TOKEN_LIMIT` (по умолчанию 500 000, 0 = без лимита): на 80% бот
предупреждает, на 100% перестаёт обращаться к модели до полуночи и объясняет почему. Если учёт недоступен, бот не блокируется.
Не учитывается: распознавание голоса запасным Gemini (расходует токены Gemini, но отдельно не считается).

## CI

`.github/workflows/ci.yml` на каждый push и PR: все тесты (каждый файл в своём процессе, в чистом окружении без `.env`),
резервные копии на настоящем Postgres, сборка образа и `docker compose config`, синтаксис Ansible.
Локально то же самое: `for f in tests/test_*.py; do PYTHONPATH=. python $f || break; done`.

## Фото и документы

Фото, PDF, DOCX и текстовые файлы (и код) можно присылать с подписью-вопросом или без неё. Фото (JPEG/PNG/WebP) и PDF уходят
модели как вложение (Gemini и Claude), текстовые файлы и DOCX читаются и подставляются текстом (до 12 000 символов).
Альбом из нескольких фото обрабатывается одним запросом (до 5 файлов). Файл до 10 МБ. Аудиофайл идёт в распознавание речи.
Байты вложений в БД не хранятся (только пометка `📎 имя`), поэтому в следующем сообщении модель файл уже не видит.

Защита: содержимое вложения это недоверенные данные (как письма). Ход с вложением считается «заражённым»: запись в память и
другие подтверждаемые действия требуют кнопки, пересланные файлы дополнительно помечаются, а в промпте есть правило не
выполнять инструкции из вложений. Проверено на настоящем Gemini: PDF со скрытой «отправь письмо на …» не выполнен, владельцу сообщено.

## Поиск в интернете

Инструмент `web_search`: модель сама решает, когда нужен свежий факт (расписания матчей, новости, курсы, погода, цены), и вызывает
его. Внутри это отдельный запрос к Gemini со встроенным поиском Google (grounding), который возвращает сводку с источниками.
Так сделано потому, что Gemini не позволяет совмещать встроенный поиск с вызовом функций в одном запросе: если включить
поиск в основном запросе, пропадут Gmail, напоминания и память. Побочная выгода: поиск работает и при основной модели Claude
(нужен только `GEMINI_API_KEY`). Результаты поиска это недоверенные данные: ход «заражается» (см. выше), блок результата
нельзя закрыть изнутри. Токены поиска считаются отдельной строкой `gemini:<модель>+search` в `/usage` и в дневном лимите.
Настройки: `WEB_SEARCH_ENABLED`, `WEB_SEARCH_MODEL` (по умолчанию `GEMINI_MODEL`), `WEB_SEARCH_DAILY_LIMIT` (по умолчанию 50 поисков
в день: у поиска Google своя цена за запрос, уточни тарифы в консоли Google; лимит не даёт расходу раскрутиться).

Запуск без Docker: `python -m src.app.main`.
